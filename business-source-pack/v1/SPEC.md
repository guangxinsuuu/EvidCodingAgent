# Business Source Pack v1：本地实验商业规则

本包是用户要求实现的合成商业上游，不是任何公司的正式退款政策、已签合同或付款证明。
执行资格为 `LOCAL_CALIBRATION`，人工政策审阅状态为 `PENDING_USER_REVIEW`。本轮实现授权
不能被写成法务、财务或真实客户批准。生产接入必须提供自己的权威来源。

## R1 适用对象与政策选择

只处理来源服务状态机产生、`term_number >= 2` 的 `SUBSCRIPTION_RENEWAL_EFFECTIVE`。
首次开通、取消和终止结算都不是续期。标准实验合同须在续期和申请两个时点有效、存在
明确的 `SIMULATED_ACCEPTANCE`，并引用本包的退款补充条款。特殊条款首期转人工补证。
默认按续期生效时点选择政策：生效区间左闭右开，不能按申请日期或最新版本选择。
本包 v1 为 2026-10-01 至 2026-11-10 UTC，v2 从 2026-11-10 UTC 起。

## R2 窗口与申请时点

v1 窗口为 14 × 86400 秒，v2 为 7 × 86400 秒；比较 UTC 经过时长，0 和窗口末端均包含。
不是自然日，也不依赖宿主机时区。申请是商业来源服务接受的不可变 RefundClaim；
claimed_at 取该订阅的实验业务时钟，原生 Chatwoot 消息 ID、真实 created_at 和正文摘要另存。
二者不是同一种时间。补充消息只能追加修订，不得移动原申请时点。模拟器只推进自己的
业务时钟，不改变操作系统、Keycloak、数据库或 Worker 租约时间。

## R3 用量规则与证明边界

统计所选指标 `metric_code` 的 `units`，不跨指标相加；要求从续期生效至申请时点的闭区间
用量不超过 0。期望事件是测试生成器预先登记的有限集合；每个事件须记录发送、接收及
原生聚合核对。缺事件、待处理、指标歧义或聚合不一致均不允许封存覆盖记录。
完整性范围固定为 `LOCAL_CONTROLLED_GENERATOR_ONLY`，不能表示公司的全部事件到齐。
原生聚合期间必须与已绑定发票的计量期间一致；区间用量只能由已核对的事件明细计算，
不能拿整期聚合冒充任意子区间。

## R4 合同、发票与付款

发票须属于同一客户、唯一订阅，费用期间与模拟续期事件期间严格一致。可以使用原生
INITIAL 发票作为明确标注的实验账单，但不能因此宣称 Lago 自然续费已验证。
现有终止关闭账单不能作为续期正例。付款须另有与发票、币种、金额一致的
`SIMULATED_PAYMENT` 记录；不得修改 Lago 的付款状态或把开票成功等同付款成功。

## R5 输出和失败语义

事实充分时给出 ELIGIBLE 或 INELIGIBLE 的本地实验资格建议；缺失、不适用、歧义或
未校准资产返回 NEEDS_MORE_EVIDENCE。文案必须标明实验范围，付款依据为模拟记录。
始终只写正确会话的私有内部备注，不退款、不对客发送、不关单。
上游服务不可用是执行失败，不伪造空资产继续，也不回退旧 fixture。

## R6 重试与重新评估

重试同操作保留原快照与 Job。新增事实必须通过显式 reevaluate 入口，记录父 Job、原因
与稳定事实摘要；新事实产生新评估，旧快照不可覆盖。只有采集时间变化不算新事实。

## 人可独立推算的校准样本

| 前提 | 变化 | 预期（仅校准器持有，来源 API 不返回本表） |
|---|---|---|
| 标准合同、有效续期、完整零用量、模拟已付款 | v1 续期后第 10 天申请，已进入 v2 生效日期 | ELIGIBLE；仍选 v1 的14天 |
| 相同充分事实 | v2 续期后第 8 天 | INELIGIBLE；超过7天 |
| 相同充分事实 | v1 正好第14天／再晚1秒 | 前者符合，后者不符合 |
| 原生聚合为0 | 有一个预计事件仍未接收 | NEEDS_MORE_EVIDENCE |
| 工单新增补充消息 | 原 claim 不变 | 原申请时间不变，不延长或缩短窗口 |
| 原生终止结算发票 | 没有成功续期状态转换 | NEEDS_MORE_EVIDENCE |
