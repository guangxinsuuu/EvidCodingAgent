## 1. 这批对象为何值得测试

新版本新增了政策版本选择、合同适用性、商业续期事件、不可变原申请、用量完整性、模拟付款和显式重评。因此测试围绕这些变化可能破坏的业务关系组织，而不是再次大范围重复稳定版本的普通问答。

一个对象并非单条输入JSON。它同时包含真实 Chatwoot 会话与原始消息、Lago 客户/订阅/发票/计量、Keycloak 租户操作身份，以及独立 Commercial Source 中的政策、合同、事件和状态。SUT 经HTTP读取这些来源，冻结输入，经过 PostgreSQL → Outbox → Redis → Worker → 本地 qwen2:7b，最终写回正确会话的私有备注。

本轮选择依据是人工按版本变化编排的风险矩阵，尚不是 Verify Agent 自动识别变化并选择测试。预期答案只在 `release_oracle.py`，没有发送给来源服务或产品，也没有调用产品的 `commercial_decision` 来计算期望。

## 5. 已确认的新版本问题

### F1：已终止订阅被不适用的当前用量查询阻断

原生订阅状态为 `terminated`。发票费用终点为 `00:55:33`，同发票历史用量终点为 `00:55:32`，且计量列表为空。准备器明确保存期间不匹配和缺失指标，没有造出零用量。

`LagoClient.resolve_invoice_scope` 在严格期间校验后令usage为空，接着不检查终止状态而尝试 `current_usage`。Lago明确返回 `405 / no_active_subscription`，通用HTTP层映射为SUT `503 / EXTERNAL_HTTP_REJECTED`。原生账单/历史用量/健康接口均200，此案例没有Job。

这是产品适配器处理缺证与不适用端点的缺口，不是环境失联，也没有依据称为Lago上游Bug。下一次修复应保留缺证事实并让业务形成补证结果，不能放宽1秒匹配或伪造续费。证据见 [terminated-investigation.json](terminated-investigation.json)，定位 `services/genai-support-sut/src/genai_support/integrations/lago.py:139`。

### F2：结论正确，但给出错误的超窗理由

迟到用量重评原文：“您的使用量已超过政策限制，且申请时间超出适用政策窗口。”

冻结事实与独立检查均证明申请间隔2天、窗口7天。`INELIGIBLE`本身正确，但“超出窗口”与事实直接矛盾。当前结构化校验没有禁止这种错误解释；仅仅校验JSON枚举不足以验收GenAI业务输出。

### F3：已存在的特殊条款被说成材料缺失

特殊合同原文：“您需要提供特殊合同条款和退款附加协议的相关证据。由于这些信息暂时缺失……”

来源已有 `special_terms=true` 和 `EGAP-LAB-SPECIAL-1`。准确解释应是“条款存在，但当前标准规则不能直接裁决，需要人工审核”。产品的 `missing_evidence` 同时输出 `SPECIAL_CONTRACT_TERMS`、`REFUND_ADDENDUM`，也混合了缺材料与不支持自动解释两类状态；不能只归责模型。

另外，币种冲突案例说“缺少模拟付款记录”，但记录实际存在，只是EUR与USD不一致。登记为解释精度待复核。7份原始草稿未显式提实验范围，自动探针均登记 `REVIEW_REQUIRED`；最终私有备注的确定性实验声明均通过检查。没有把这些备注误报成已经对外发送。

上述文案问题来自事后逐份查看13份输出与冻结事实，不是现有词汇探针自动证明的完整语义结论。原始自动运行结果没有被改写，完整清单见 [findings.json](findings.json)。

## 6. 准备期间遇到的真实系统行为

第一次尝试在11月10日新建回溯到11月9日的Lago订阅，订阅激活但未立即产生首次账单，120秒有界观察后准备停止。读取本机固定版本的Lago源码，过去日期分支与当天激活计费分支不同。因此改为显式复用已有11月9日真实账单，核验客户、订阅、期间与指标，并新建本轮会话；没有运行内部Rails补账任务或修改数据库制造历史。

首次未完成尝试保存在 `native-initial-attempt/`，其8条已完成操作及已创建资源仍有账本，没有将旧失败回执覆盖为成功。它是准备限制，未算SUT缺陷。

终止账单的一秒期间差异也保留在对象中。只有该负例允许“不具备用量资格”的对象进入验证；普通资格样本仍严格要求期间精确匹配。这个真实差异最终暴露了F1，而非被准备器抹平。

## 7. 哪些是真实系统行为，哪些是合成实验条件

真实部分：Chatwoot消息/私有备注、Lago客户/发票/订阅终止/用量事件及聚合、Keycloak登录、数据库事务、Redis队列、Worker与模型调用、HTTP故障及恢复。

合成部分：公司退款规则、合同和 `SIMULATED_ACCEPTANCE`、商业续期事件、申请业务时刻、`SIMULATED_PAYMENT`。规则仍待用户审阅，未伪造财务/法务/客户批准；没有真实支付商或资金流水。

两个时钟必须区分：真实请求、原生消息/事件创建和观察回执发生在11月10日；商业时钟可推进至11月19日。事件另有预登记的原生timestamp与真实发送observed_at。申请后用量案例并未在真实时间等待三天。普通首次账单映射到模拟续期事件，不证明Lago自然续期调度正确。

用量完整性只覆盖受控生成器预登记的有限事件集合。当前本地规则检查器没有独立基础设施防篡改、签名Final证据或企业业务批准资格，也没有完成LangGraph Verify Agent。本次检查没有证明所有证据引用关系或全部自然语言语义都正确。

工具还有一个本轮未触发的边界：网络连接失败/缺HTTP回执可能在边界驱动中记为FAIL，应在后续工具增强时区分观察INCOMPLETE。本轮12项边界均有明确响应，不受该问题影响。独立Oracle也只要求必要缺项存在，不证明附加缺项全部合理，F3由事后复核发现。
