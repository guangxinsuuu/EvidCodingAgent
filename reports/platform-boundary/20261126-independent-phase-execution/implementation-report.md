## 3. 新代码与调用关系

`phase_runtime.py main → PhaseExecution.run → run_case → step → ExperimentLedger.execute → 受控操作端口`。

| 入口/函数 | 职责与实际边界 |
| --- | --- |
| `PhaseExecution.__init__` | 核验候选绑定，在 PostgreSQL 的 `independent_phase_ledger` 冻结实验候选、配置和计划版本；不将数据库凭据放入输入或报告 |
| `step` | 派发前重验实物；记录 EGAP commit 和工具文件摘要；完成操作复用原证据，UNKNOWN 不自动重发 |
| `source_step` | 使用准备者执行预登记事件发送、接收登记、核对和封存；链接已有原生/商业子账本。只有真实 POST 回执才标记已发送 |
| `submit` | 通过普通客服身份调用产品 API；每个提交/复评有固定 operation_key；HTTP 超时不换键补投 |
| `wait_job` | 观察同一 Job，最多三轮、每轮 120 秒；每次完整观察立即落证据。DONE 不等于原件完整，缺模型原件时仍保留缺项 |
| `aggregate` | 用新的观察 ID 查询同一指标和账期；零值保持 PENDING，不能借此封存；每次运行最多 30 次、总计最多 90 次 |
| `run_case` | 组合 OPEN → J1 → 事件 → 聚合 → 接收/核对/封存 → 原请求重试 → J2 → 旧快照读回；必需阶段不足时不推进后续写入 |
| `phase_observe.py PhaseObserver` | 独立装配只读客户端。读取产品 GET/只读 SQL、原生 OBSERVER、商业 OBSERVER 和模型出口 OBSERVER；不加载准备器或候选代码 |
| `model_trace` | 取得实际 wire 请求/响应，并核对摘要、Job、租户、工单版本、模型权重、Gateway 回执和最终草稿。绑定失败不提供可信 decision |
| `ChatwootReadPort` | 使用有界分页取得消息；首屏不能被当作完整历史，缺原客户消息时明确留缺口 |

`phase_experiment.parser` 只增加可复用动作枚举参数，运行入口共用明确的候选/来源参数，不向 Agent 开放任意 URL、shell 命令或凭据参数。

准备者和观察者使用不同服务凭据；本机操作员控制器仍可访问两组配置，Python 对象分离不等于企业进程、主机或 IAM 隔离。当前结果限定于已授权本地合成环境。

## 4. 真实中断与恢复证据

第一次执行在 `late_usage.dispatch` 已提交后调用 `os._exit(75)`，实际进程以 75 退出。中断点位于原生事件发送后、聚合观察前。

- 中断时：1 个 Job、1 次交付、1 次模型调用、1 条主事件；前四个操作全部持久化为 COMPLETED。
- 新进程恢复：前四个操作复用原回执，继续原实验身份，没有重发主事件或重建 J1。
- 两组完成：24 个操作全部 COMPLETED；每个 dispatch_count=1，无 UNKNOWN 或遗留 DISPATCHED。
- 再次运行完整流程：24 个操作全部重放；仍为原四个 Job、四次交付和四次模型调用。
- 商业 POST 回执保持 26 条，其中准备 18 条、阶段推进 8 条。
- 原生事件 POST 回执保持 4 条，其中准备时的干扰指标事件 2 条、本轮两条主指标事件 2 条；不能把这四条全部说成迟到主事件。
- 112 份 PG 操作证据引用逐项 SHA-256 校验一致。账本事件、原始观察和报告时刻快照保留。

这一真实实验验证的是“已提交步骤后中断”的恢复，不是所有网络未知窗口均已在业务系统实测。已有 PostgreSQL 测试另行验证进程崩溃留下 UNKNOWN、只读对账和禁止自动重新派发。本轮没有为原生事件 UNKNOWN 增加自动对账适配器。
