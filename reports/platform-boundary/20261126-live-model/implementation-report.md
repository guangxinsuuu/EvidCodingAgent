本轮完成了独立产品容器 → 受限模型出口 → 本机已安装 Ollama → 独立原件观察的真实链路。

## 具体变更与调用关系

1. `tools/model-boundary/proxy.py`：受信模型出口。只代理固定宿主的 `/api/tags` 和 `/v1/chat/completions`；客户端不能选择任意 URL、其他模型、下载路由或工具。产品调用 token 与原件观察 token 分开。
2. `tools/model-boundary/Dockerfile`：出口单独镜像，非 root、只读根文件系统；原始请求、响应和预算保存在本部署专有 SQLite 卷。
3. `tools/product-boundary/model_attachment.py`：操作员在首次启动前冻结模型、权重摘要、预算、租约和出口镜像；仅 Gateway 接专用内部模型网络，API/Worker/Relay 不取得模型调用或原件观察凭据。出口另外接宿主访问网络；这是本机容器边界，不是企业级网络隔离。
4. `tools/product-boundary/product.py` 与 `deployment.py`：把模型装配纳入候选部署冻结、恢复核验和实际端口发现。
5. `tools/product-boundary/observe_native.py`：在原生业务观察上增加真实模型原件读取。检查 wire 字节摘要、Job/租户/工单修订、模型清单、Gateway 回执、保存文案及实际私有备注之间的关系。模型失败或交付缺失会保留缺项，不再假定一定有成功交付对象。
6. `tools/product-boundary/verify_model.py`：核对重启后的原件，使用原操作和原字节回放，并执行产品读原件、观察者推理、无效身份、下载路由、额度扩大及同键改载荷的拒绝检查。
7. 独立产品 `model_gateway.py` / `container_runtime.py`：修正容器模型健康检查原先写死 `127.0.0.1` 的问题；使用登记 origin，携带专用模型 token，以 Job ID 关联出口操作。Job ID 放在传输头，不加入客服 Prompt。

实际调用链：

```text
受信 product.up
  → 固定产品 Git 构建回执
  → 平台 / 商业来源 / 模型出口装配
  → 冻结角色配置与镜像

普通客服 OIDC 身份 → 产品 API → 独立产品数据库 / Redis → Worker
  → 产品 Gateway → 产品业务工具决定 → 模型出口 → 本机 Ollama
  → 原始模型响应 → 产品保存草稿 → Chatwoot 私有备注

独立观察者
  → 产品只读数据库 + 原生平台 GET + 商业来源 OBSERVER
  → 模型出口 OBSERVER 原件
  → 关联核对与私有证据文件
```

出口先在事务中登记调用和预算，再单次发送推理。同一出口同时最多一条登记为 DISPATCHED 的 HTTP 请求；同键不同请求冲突。超时、缺回执、5xx 或重启中断保留 UNKNOWN 与额度，不自动补发。UNKNOWN 不证明 Ollama 后台计算已经停止，当前也没有供应商取消确认协议；调用总额仍受八次预留约束。完成操作回放返回原始响应；观察接口不生成新推理。

每个案例的 10 项检查分别覆盖：相同 Job 和输入、相同完成草稿、外部事实快照、原生私有备注正文与目的地、跨租户拒绝、模型操作身份、模型输入绑定、模型输出绑定、模型文案与保存草稿相等、独立商业来源读回与产品冻结事实相等。

## 重启、拒绝和资源验证

- 五份原始模型操作在出口重启后内容不变。
- 同一操作的有效回放返回相同原始响应；调用预留仍为 5，未增加模型推理。
- 产品 token 读原件返回 403；观察 token 发推理返回 403；错误身份返回 401。
- 下载路由返回 403；输出上限扩大返回 422；同一操作修改请求返回 409。
- 同一业务 Run 恢复后，真实 PostgreSQL 中仍是 5 个 DONE Job、5 个 COMPLETE 交付和 5 个 COMPLETE / LIVE_MODEL 调用。
- 重启时发现 Docker Desktop 改变了模型出口随机发布端口；旧地址连接拒绝。恢复验收已改为先从 Docker 重新取得实际回执，再对账。没有用旧端口猜测新的服务。
- 为给新模型网络留出容量，分别核对 `evid-sut-bd15fa5ea3e8` 和 `evid-sut-bfc87d2f47f2` 的五项任务全部完成后，移除其专有容器和网络。数据卷、原始证据、冻结配置均保留。旧 `egap-multisystem` 等用户服务未改动。
