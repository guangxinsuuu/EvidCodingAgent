## 必须保留的模型不足

本轮模型读到了三份原件，却只把 E1 草稿标记为 `PROVIDED`，把 E2 私有备注、E3 交付回执标记为 `PARTIAL`，表示尚需确认最终消息 ID 和交付关系。

实际原件与已读回执中，备注和交付记录的 `external_message_id` **均为 52**；交付回执也包含准确的备注引用与正文摘要。因此，这是模型没有充分使用已获得的关联信息，不能解释成原件真的缺少消息 ID。Runtime 接受的是合法的保守未完成提案，没有独立证明这两项数据缺失，也没有自动把它升级成 `PROVIDED`。

浏览器验收通过的是“真实响应和缺口可查看、限定接受不消除缺口、显式撤回保留审计”的产品流程，**不是本轮模型完整作答成功**。未修改 Prompt、未补造输出、未重跑模型直到得到满意结果。原输出、缺口、回执和成本都保留。后续模型改进应针对如何使用已经取得的消息 ID、引用与摘要完成关联推断，另设评测；不能拿本次已公开案例计算未见任务准确率。

本轮新增 4 次模型调用、3 次 MCP 读取，输入 23,837 tokens、输出 2,030 tokens；本案累计 21 次模型调用、15 次读取，预留归零，上限仍为 24 / 48。浏览器刷新、重新登录、查看原件、接受和撤回没有新增模型调用。工作台查看原件是授权 HTTP 读取，不重复计成 Agent 的 MCP 读取。

## 实际页面发现与修正

真实页面暴露了字面 `null`：`el()` 本来会过滤条件占位，但任务列表、任务详情及历史材料页直接调用原生 `append` / `replaceChildren`，把空的 flash 消息转成了文本。

`apps/review-workbench/public/app.js` 现在通过 `contentNodes()`、`appendContent()`、`replaceContent()` 共用子节点处理，仅跳过 `null`、`undefined`、`false`，保留数字 `0` 和正常文本；没有加入 `innerHTML` 通道。任务页刷新后已实际观察到占位文本消失。

UI 测试新增任务列表／详情空提示、真实提示与数字 0 的回归，16/16 通过。构建、TypeScript 类型检查、JavaScript 语法和 diff 检查通过。本轮没有改动后端协议、模型提示词或公司验收规则。

私有截图与无障碍树证据保存在本地 `artifacts/review-workbench/browser-coverage/<case-id>/browser-*`，包括勾选表单、原件／回执、撤回后状态和最终任务列表。截图含浏览器周边信息，保持私有，不提交 Git。脱敏数据库核对结果见 [validation-summary.json](validation-summary.json)。

期间曾出现原生连接中断、切换窗口后的操作保护，以及扩展接口不可用。重连后从 Chrome 窗口菜单选回工作台，并重新绑定当前窗口，最终完成上述实际点击；没有使用脚本模拟点击或绕过 UI 提交人员命令。
